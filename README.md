# English Typing Practice

一个纯前端的英文文章打字练习工具。

导入一篇英文文章后，原文与输入框逐行对照显示：左侧是导入 / 主打字区，右侧是浅色信息侧边栏。正常英文下原文和输入内容逐字符横向对齐；颜色反馈只标在原文行上，输入框本身保持普通文本编辑体验。

> React 18 · TypeScript · Umi 4 · 本地词库 · 无后端

## 功能概览

### 左右栏工作区

- **起始页**：左侧粘贴文章 / 导入 TXT，右侧放练习设置与使用提示；
- **打字页**：左侧是原文、输入框和行内状态，右侧集中显示进度、速度、正确率、错误数、设置和完成信息；
- 桌面端整页是固定视口的圆角应用框，左右两栏纵向撑满；窄屏（≤900px）自动切换为上下排列。

### 原文与输入框对齐

- 原文行和下方输入框使用同一套等宽字体、字号、左右 padding 和边框；
- 正常英文下字符位置一一对齐，错误标记不会改变字符宽度；
- 每行最大字符数按**实际字体宽度和实际可用布局宽度**计算，再按单词边界拆分，不会固定使用一个偏小的字符数；
- 字符太宽、字体 fallback、浏览器缩放等极端情况仍可能出现细微偏差，但常规英文正文对齐是稳定的。

### 普通输入框 + 原文着色

- 输入框是普通 `<input>`：支持点击定位、←/→、Home/End、Shift+方向、鼠标拖选、输入、退格和 Delete；
- 输入内容保持普通颜色；
- 正确字符在**原文行**显示绿色；错误字符显示为深红底白字；
- 连续错误合并为一个连续圆角红块，不会出现每个字母各自一个圆角的碎片效果。

### 跳过字符

可分别设置跳过：

- 空格
- 标点
- 数字
- 换行符

规则：

- 默认全部关闭；
- 开启跳过后，对应字符会自动填入输入框，包括换行 `↵`；
- 手动输入被跳过类别的字符会被忽略；
- 退格到自动跳过字符时，会继续退掉前一个正常字符；
- 在设置被修改但尚未应用时，练习页会显示“未应用”胶囊；
- 点击“应用并重新开始”会从文章开头重新计时。

### 换行符与 Enter

- 输入框会把换行显示为 `↵`；
- Enter 被当作普通字符输入，不再有“跳到下一行”的特殊行为；
- 多按 Enter 会被计为错误字符；
- 开启“跳过换行符”后，`↵` 会自动补入，完成当前段落后自动进入下一段。

### 行切换与编辑

- 鼠标点击任意原文行或输入框，可以直接切换当前行；
- 点击输入框内部可以精确放置光标；
- `↑` / `↓` 在行之间上下切换，并尽量保持光标列；
- 在行首继续按 `←` 跳到上一行末尾；
- 在行尾继续按 `→` 跳到下一行开头；
- 带 Shift/Ctrl/Alt 的方向键保留原生选择或移动行为；
- 回到前面的行修正时，后续行内容不会丢失，不需要先退格掉所有后面内容。

### 打字信息

右侧信息栏实时显示：

- 行号；
- 已输入单词 / 总单词；
- 已输入字符 / 需输入字符；
- 词库覆盖率；
- 速度 WPM、正确率、用时、错误数；
- 当前进度条。

鼠标悬停“词库覆盖”可以查看当前文章里未收录的单词；覆盖率按不重复单词统计。

### 完成状态

- 没有独立的“练习完成”结果页；
- 打完最后一行后，右侧普通信息卡直接切换为绿色渐变完成态，显示“已完成”；
- 用时、WPM、正确率、错误数会被锁定；
- 完成后仍然可以退格修改、继续输入、切换行或点击单词查词；
- 通过“应用并重新开始”或换文章开始新一轮练习。

### 点击查词

- 点击原文中的任意单词，显示释义卡片；
- 卡片包含中文释义、音标、词形变化、考纲标签和 BNC / 当代词频；
- 悬浮卡会根据单词位置自动选择在单词上方或下方展示；
- 连字符复合词会拆分查词，例如：
  - `algorithm-driven` → `algorithm` + `driven`
  - `cross-check` → `cross` + `check`
- 变形词回退：`wrapped`、`went`、`was` 等会回退到原形词条；
- 词库为本地数据，首次开始练习时动态加载，不请求外部词典服务。

## 使用流程

1. 在起始页粘贴文章，或导入不超过 1MB 的 UTF-8 `.txt` 文件；
2. 在右侧调整跳过设置（可选），点击“开始练习”；
3. 在输入框中按原文输入；正确 / 错误反馈即时显示在原文行；
4. 需要修正时点击目标行，或使用方向键切换；
5. 完成后查看右侧锁定成绩；仍可继续修改或查词；
6. 修改设置并应用，或换一篇文章，开始新一轮。

### 输入限制

- 单个 TXT 文件最大 1MB；
- 文章最多 500,000 个字符；
- 文章最多 20,000 个英文单词。

## 统计口径

### WPM

```text
WPM = 正确字符数 / 5 / 用时（分钟）
```

- 只统计与原文一致的正确字符；
- 错误字符不计入 WPM；
- 空格如果命中原文空格也会计入；
- 正确率单独计算为 `正确字符数 / 已输入字符数`。

因此这是**净 WPM**：在低正确率、大量输入空格时，WPM 也可能偏高，需要结合正确率一起看。

### 单词进度

- 单词进度按“该单词最后一个字符是否已经输入”统计；
- 单词拼错但已经输入完整，仍算已输入；
- “已输入 / 总单词”会随编辑实时更新。

### 词库覆盖率

- 按文章中的不重复单词统计；
- 完整词条存在即算覆盖；
- 连字符复合词只有所有组成部分都能查到才算覆盖；
- 变形词和原形词共用同一套词库。

## 本地开发

环境要求：

- Node.js >= 20；
- pnpm（项目使用 pnpm 12；Node 24 环境可直接运行）。

```bash
pnpm install
pnpm dev       # http://localhost:8000/
pnpm build     # 生产构建，输出到 docs/
```

类型检查：

```bash
pnpm exec tsc --noEmit
```

`pnpm build` 会生成可直接静态部署的 `docs/` 目录；项目没有后端依赖。

pnpm 12 默认会拦截依赖构建脚本，本项目在 `pnpm-workspace.yaml` 的 `allowBuilds` 中放行了 `esbuild`、`core-js` 和 `core-js-pure`。

## 词库

### 数据来源

Web 词库由本地 ECDICT / ecdict-revised 合并生成：

- [ECDICT](https://github.com/skywind3000/ECDICT)：基础词条、考纲标签、词频、词形等；
- [ecdict-revised](https://github.com/sliuhaob/ecdict-revised)：中文译文本体与修订内容。

前端使用 `src/data/generated/dictionary.json`：

- 约 44,500 个 headwords + 29,000 个变形/别名节点；
- 文件约 6.8MB，gzip 约 2.1MB；
- 首次开始练习时动态加载；
- 支持考纲标签、音标、词形、词频和连字符复合词拆分。

### 生成流程

词典工具使用 Node 内置 `node:sqlite`，需要 Node.js >= 22.5。

```bash
cd tools/dict
bash fetch-data.sh     # 首次下载原始数据（约 110MB）
node build.mjs         # 生成 data/dict.sqlite（约 73MB）
cd ../..
pnpm dict:app          # 生成 src/data/generated/dictionary.json
```

详细说明见 [tools/dict/README.md](tools/dict/README.md)。

### 收录策略

前端词典不是完整 78 万词条数据库，而是面向阅读练习的精简子集：

- 优先保留考纲词、高频词、核心词；
- 补充常见 BNC 排名词，避免 `an` 这类在源数据里缺少 FRQ / 考纲标签的常见词漏收；
- 变形词通过别名节点回退到原形；
- 连字符复合词按各组成部分判断收录；
- 不保证生僻词、专有名词和部分短语都会被收录。

## 已知限制

- 纯前端内存状态：刷新页面后当前文章、练习进度和设置都不会持久化，也不做账号同步；
- 没有真人发音、例句或跨设备记录；
- 词库是精选子集，生僻词、专有名词和部分短语会显示“未收录”；
- 行对齐依赖系统等宽字体 fallback 和浏览器文本渲染；极端字体 / 缩放环境下可能出现轻微偏差；
- WPM 是净 WPM，不直接等于原始敲击速度；
- 当前没有独立自动化测试套件，提交前主要使用 `tsc --noEmit`、`pnpm build` 和浏览器交互联调验证。
